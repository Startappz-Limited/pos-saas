# Web & API Controller Sync Guide

## 1.1.1 Core Rule

> **When a web controller is updated, its API counterpart MUST be updated to reflect the same changes — and vice versa.**

Web controllers live in `app/Http/Controllers/` and API controllers live in `app/Http/Controllers/Api/`. They share the same business logic and must stay in sync.

## 1.1.3 What Requires Syncing

Any of the following changes in a web controller must be mirrored in the API controller:

- **New endpoints** — add the equivalent API endpoint returning JSON
- **Business logic changes** — queries, filters, validations, calculations
- **New relationships or eager loads** — ensure API returns the same data
- **Status transitions or workflow changes** — same rules must apply
- **New Form Request rules** — share the same Form Request or replicate rules
- **Bug fixes** — if the bug exists in both controllers, fix both

## 1.1.4 Key Differences Between Web and API

API controllers differ from web controllers only in their response format:

| Aspect | Web Controller | API Controller |
|--------|----------------|----------------|
| Response | `view()` / `redirect()` | `response()->json()` |
| Auth | Session-based | Sanctum token-based |
| Errors | Flash messages / redirects | JSON error responses |
| Pagination | Blade pagination links | JSON paginated response |

Business logic, validation, authorization, and data access must remain identical.

## 1.1.5 Checklist

When modifying any controller:

- [ ] Identify if a counterpart controller exists (web ↔ API)
- [ ] Apply the same logic change to the counterpart
- [ ] Ensure shared Form Requests are used where possible
- [ ] Update API routes in `routes/api.php` if new endpoints are added
- [ ] Run tests for both web and API to verify no regressions
