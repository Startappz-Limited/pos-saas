# UI Design Guide

## Raw HTML Design Templates

All raw HTML design templates and theme assets are available at:

```
./designs/theme/
```

These templates serve as the source of truth for UI implementation and should be referenced when building Laravel Blade components.

---

## 2.1 UI Philosophy

The UI is built on the following principles:

- Consistency over creativity
- Predictability over novelty
- Reusable components over one-offs
- Enum-driven states
- Accessibility by default

> **Core Principle:** The UI must reflect system state accurately and must never infer or guess backend logic.

## 2.2 Design System Ownership

The design system is centralized but consumed modularly.

```
resources/
├── design-system/
│   ├── tokens/
│   ├── components/
│   ├── layouts/
│   └── themes/
└── modules/
```

> **Rule:** Modules consume, not redefine, design rules.

## 2.3 Theme Breakdown

### 2.3.1 Color System

**Brand Color Palette (example tokens — replace with your project's brand colors):**

**Primary Colors:**

- **Bright Green:** `#C5C470` - Primary brand color
- **Medium Green:** `#A8C963` - Secondary brand accent
- **Light Green:** `#D9EFAA` - Light accent/backgrounds
- **Cream:** `#FFF7EE` - Light neutral background

**Accent Colors:**

- **Purple:** `#462350` - Dark accent/contrast
- **Yellow:** `#FFE202` - Warning/highlight color
- **Dark Green:** `#001E0A` - Deep brand color
- **White:** `#FFFFFF` - Pure background
- **Pink:** `#FFD2D2` - Light error/warning background

**Semantic colors must map to Enums:**

| Enum Value  | Color Token | Hex Code  |
| ----------- | ----------- | --------- |
| `ACTIVE`    | `success`   | `#A8C963` |
| `INACTIVE`  | `muted`     | `#FFF7EE` |
| `SUSPENDED` | `warning`   | `#FFE202` |
| `FAILED`    | `danger`    | `#FFD2D2` |

> **Rule:** UI colors must never be hard-coded. Always use the defined brand colors.

## 2.4 Typography

### 2.4.1 Font Stack

**Primary Font:**

- Used for headings and primary content
- Weights available: Semi-bold, Regular
- Character set: Full Latin alphabet, numbers, symbols

**Secondary Font:**

- Used for metadata, labels, helper text
- Character set: Full Latin alphabet, numbers, symbols

**Fallbacks:**

- System fonts only

```css
/* Primary font */
font-family:
    'PrimaryFont',
    -apple-system,
    BlinkMacSystemFont,
    sans-serif;

/* Secondary font */
font-family:
    'SecondaryFont',
    -apple-system,
    BlinkMacSystemFont,
    sans-serif;
```

### 2.4.2 Font Usage Rules

| Element     | Font  | Weight    |
| ----------- | ----- | --------- |
| Heading 1   | Primary | Semi-bold |
| Heading 2   | Primary | Semi-bold |
| Heading 3   | Primary | Semi-bold |
| Heading 4-6 | Primary | Semi-bold |
| Body text   | Primary | Regular   |
| Paragraphs  | Primary | Regular   |
| Labels      | Secondary | Regular   |
| Helper text | Secondary | Regular   |
| Metadata    | Secondary | Regular   |

## 2.5 Spacing & Layout System

**Spacing Unit:**

- Base unit: `4px`
- Scale: `4, 8, 12, 16, 24, 32, 48`

**Rules:**

- No arbitrary spacing
- Margins and padding must follow scale
- Grid-based layouts only

## 2.6 UI Elements (Atomic Level)

### Buttons

**Variants:**

- Primary
- Secondary
- Destructive
- Ghost

**Rules:**

- One primary button per screen
- Destructive actions must be visually explicit

### Forms

**Rules:**

- Validation messages come from backend responses
- Required fields must be explicit
- Enum fields must be dropdowns or radios

### Tables

**Rules:**

- No horizontal scrolling unless unavoidable
- Status columns must use semantic badges
- Actions grouped consistently

### Modals

**Rules:**

- No deep modal nesting
- Confirmation required for destructive actions
- Close actions always visible

## 2.7 Widgets & Reusable Components

Widgets are composite components built from atomic elements.

**Examples:**

- User Card
- Status Badge
- Metric Tile
- Confirmation Dialog

**Rules:**

- Stateless where possible
- Configured via props only
- No direct API calls inside widgets

## 2.8 Enum-Driven UI States

> **Rule:** UI state must reflect backend Enum values exactly.

**Example:**

| Backend Enum            | UI Representation |
| ----------------------- | ----------------- |
| `UserStatus::ACTIVE`    | Green badge       |
| `UserStatus::SUSPENDED` | Yellow badge      |
| `UserStatus::INACTIVE`  | Grey badge        |

**No frontend-specific status derivation is allowed.**

## 2.9 Accessibility Standards

**Mandatory:**

- Contrast ratio ≥ WCAG AA
- Keyboard navigable
- Screen-reader labels for form inputs
- Focus indicators must be visible

## 2.10 Responsive Behavior

**Breakpoints:**

- Mobile
- Tablet
- Desktop

**Rules:**

- Mobile-first design
- No feature loss across breakpoints
- Tables adapt to cards on small screens

## 2.11 Brand Assets

**Brand Logo:**

- Primary brand mark: your project's logo/wordmark and icon
- Available in light and dark variants
- Logo files located in `./designs/theme/` directory
- Small scale version: Circle icon only

**Logo Usage Rules:**

- Maintain proper spacing around logo
- Do not modify logo colors
- Use appropriate variant for background contrast
- Minimum size requirements must be followed

## 2.12 Asset Management

**Rules:**

- Assets must be module-scoped where applicable
- Shared assets belong to `design-system`
- No inline base64 images
- SVG preferred for icons
- Brand assets must maintain consistency

## 2.13 Forbidden UI Anti-Patterns

- ❌ Hard-coded colors
- ❌ Inline styles
- ❌ UI-only business rules
- ❌ Frontend-derived statuses
- ❌ Inconsistent button meanings
