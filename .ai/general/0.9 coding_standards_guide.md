# Coding Standards & Architecture Guide

## Overview
This guide establishes coding standards for writing lean, clean, and maintainable Laravel code. It covers architectural patterns, code organization, and performance best practices.

---

## 1. Clean Code Principles

### 1.1 Code Comments
- **Keep comments short and meaningful** - explain WHY, not WHAT
- Code should be self-documenting through clear naming
- Only add comments when the logic is complex or non-obvious

```php
// ❌ Bad - stating the obvious
// Loop through users
foreach ($users as $user) {
    // Send email to user
    $user->sendEmail();
}

// ✅ Good - explaining the why
// Process users in chunks to avoid memory exhaustion
foreach ($users->chunk(100) as $chunk) {
    ProcessUserChunk::dispatch($chunk);
}

// ✅ Good - explaining complex business logic
// Grace period is 3 days after policy expiration per underwriting rules
$gracePeriodEnd = $policy->expires_at->addDays(3);
```

### 1.2 Method Length
- Keep methods small (ideally under 20 lines)
- One method should do one thing
- Extract complex logic into separate methods

```php
// ❌ Bad - method doing too much
public function processPayment($data)
{
    $user = User::find($data['user_id']);
    if (!$user) {
        throw new Exception('User not found');
    }
    
    $amount = $data['amount'];
    if ($amount <= 0) {
        throw new Exception('Invalid amount');
    }
    
    $payment = Payment::create([...]);
    $transaction = Transaction::create([...]);
    
    // Send notification
    Mail::to($user)->send(new PaymentReceived($payment));
    
    return $payment;
}

// ✅ Good - separated concerns
public function processPayment(PaymentData $data): Payment
{
    $this->validatePaymentData($data);
    
    $payment = $this->createPayment($data);
    
    $this->notifyUser($payment);
    
    return $payment;
}
```

### 1.3 Naming Conventions
```php
// Classes: PascalCase
class PolicyService {}
class ProcessPaymentJob {}

// Methods: camelCase, descriptive
public function calculatePremium() {}
public function isEligibleForClaim() {}

// Variables: camelCase, meaningful
$activePolicy = Policy::active()->first();
$premiumAmount = 1500;

// Constants: UPPER_SNAKE_CASE
const MAX_DEPENDANTS = 5;
const GRACE_PERIOD_DAYS = 30;
```

## 2. Laravel Architecture Patterns

### 2.1 Directory Structure
```
app/
├── Actions/           # Single-purpose action classes
├── Console/          # Artisan commands
├── Events/           # Domain events
├── Exceptions/       # Custom exceptions
├── Helpers/          # Helper functions
├── Http/
│   ├── Controllers/  # HTTP request handlers
│   ├── Middleware/   # HTTP middleware
│   ├── Requests/     # Form requests (validation)
│   └── Resources/    # API resources (transformers)
├── Jobs/             # Queued jobs
├── Listeners/        # Event listeners
├── Models/           # Eloquent models
├── Notifications/    # Notification classes
├── Observers/        # Model observers
├── Policies/         # Authorization policies
├── Providers/        # Service providers
├── Rules/            # Custom validation rules
├── Services/         # Business logic services
└── Traits/           # Reusable traits
```

### 2.2 Actions
Use for **single-purpose operations** that can be reused across the application.

```php
namespace App\Actions;

class CreatePolicyAction
{
    public function execute(array $data): Policy
    {
        // Single responsibility: create a policy
        return Policy::create([
            'user_id' => $data['user_id'],
            'type' => $data['type'],
            'premium' => $this->calculatePremium($data),
            'status' => PolicyStatus::ACTIVE,
        ]);
    }
    
    private function calculatePremium(array $data): float
    {
        // Premium calculation logic
        return $data['base_amount'] * $data['rate'];
    }
}

// Usage in controller
public function store(StorePolicyRequest $request)
{
    $policy = app(CreatePolicyAction::class)->execute($request->validated());
    
    return PolicyResource::make($policy);
}
```

### 2.3 Services
Use for **complex business logic** that involves multiple models or operations.

```php
namespace App\Services;

class PolicyService
{
    public function __construct(
        private CreatePolicyAction $createPolicy,
        private NotificationService $notificationService
    ) {}
    
    public function activatePolicy(User $user, array $policyData): Policy
    {
        // Orchestrate multiple operations
        $policy = $this->createPolicy->execute($policyData);
        
        $this->assignBeneficiaries($policy, $policyData['beneficiaries'] ?? []);
        
        $this->notificationService->sendPolicyActivation($user, $policy);
        
        event(new PolicyActivated($policy));
        
        return $policy;
    }
    
    private function assignBeneficiaries(Policy $policy, array $beneficiaries): void
    {
        foreach ($beneficiaries as $beneficiary) {
            $policy->beneficiaries()->create($beneficiary);
        }
    }
}
```

### 2.4 Jobs
Use for **time-consuming or queued operations**.

```php
namespace App\Jobs;

class ProcessBulkPolicyRenewal implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;
    
    public function __construct(
        private Collection $policyIds
    ) {}
    
    public function handle(PolicyService $policyService): void
    {
        // Process policies in batches to avoid memory issues
        Policy::whereIn('id', $this->policyIds)
            ->chunk(50, function ($policies) use ($policyService) {
                foreach ($policies as $policy) {
                    $policyService->renewPolicy($policy);
                }
            });
    }
}

// Usage
ProcessBulkPolicyRenewal::dispatch($policyIds);
```

### 2.5 Events & Listeners
Use for **decoupled side effects** after important domain actions.

```php
namespace App\Events;

class PolicyActivated
{
    public function __construct(
        public Policy $policy
    ) {}
}

namespace App\Listeners;

class SendPolicyActivationNotification
{
    public function handle(PolicyActivated $event): void
    {
        // Send notification when policy is activated
        $event->policy->user->notify(
            new PolicyActivatedNotification($event->policy)
        );
    }
}

namespace App\Listeners;

class LogPolicyActivation
{
    public function handle(PolicyActivated $event): void
    {
        // Audit log - separate concern from notification
        AuditLog::create([
            'event' => 'policy.activated',
            'model_type' => Policy::class,
            'model_id' => $event->policy->id,
        ]);
    }
}

// Register in EventServiceProvider
protected $listen = [
    PolicyActivated::class => [
        SendPolicyActivationNotification::class,
        LogPolicyActivation::class,
    ],
];
```

### 2.6 Observers
Use for **model lifecycle hooks** (creating, created, updating, updated, etc.).

```php
namespace App\Observers;

class PolicyObserver
{
    public function creating(Policy $policy): void
    {
        // Generate policy number before creation
        $policy->policy_number = $this->generatePolicyNumber();
    }
    
    public function updated(Policy $policy): void
    {
        // Clear cache when policy is updated
        Cache::forget("policy:{$policy->id}");
    }
    
    public function deleted(Policy $policy): void
    {
        // Soft delete related records
        $policy->claims()->delete();
        $policy->payments()->delete();
    }
    
    private function generatePolicyNumber(): string
    {
        return 'POL-' . now()->format('Ymd') . '-' . Str::random(6);
    }
}

// Register in AppServiceProvider
public function boot(): void
{
    Policy::observe(PolicyObserver::class);
}
```

### 2.7 Form Requests
Use for **validation and authorization** of incoming requests.

```php
namespace App\Http\Requests;

class StorePolicyRequest extends FormRequest
{
    public function authorize(): bool
    {
        return $this->user()->can('create', Policy::class);
    }
    
    public function rules(): array
    {
        return [
            'type' => ['required', 'string', Rule::in(PolicyType::values())],
            'user_id' => ['required', 'exists:users,id'],
            'premium' => ['required', 'numeric', 'min:0'],
            'beneficiaries' => ['nullable', 'array'],
            'beneficiaries.*.name' => ['required', 'string'],
        ];
    }
    
    public function messages(): array
    {
        return [
            'type.in' => 'Invalid policy type selected.',
        ];
    }
}
```

### 2.8 Policies
Use for **authorization logic**.

```php
namespace App\Policies;

class PolicyPolicy
{
    public function view(User $user, Policy $policy): bool
    {
        // User can view their own policies or admins can view all
        return $user->id === $policy->user_id 
            || $user->hasRole('admin');
    }
    
    public function update(User $user, Policy $policy): bool
    {
        // Only active policies can be updated by owner
        return $user->id === $policy->user_id 
            && $policy->status === PolicyStatus::ACTIVE;
    }
}
```

### 2.9 Custom Rules
Use for **reusable validation logic**.

```php
namespace App\Rules;

class ValidPolicyDuration implements Rule
{
    public function passes($attribute, $value): bool
    {
        // Policy duration must be 1, 6, or 12 months
        return in_array($value, [1, 6, 12]);
    }
    
    public function message(): string
    {
        return 'Policy duration must be 1, 6, or 12 months.';
    }
}

// Usage
'duration' => ['required', new ValidPolicyDuration],
```

### 2.10 API Resources
Use for **consistent API response formatting**.

```php
namespace App\Http\Resources;

class PolicyResource extends JsonResource
{
    public function toArray($request): array
    {
        return [
            'id' => $this->id,
            'policy_number' => $this->policy_number,
            'type' => $this->type,
            'status' => $this->status,
            'premium' => $this->premium,
            'starts_at' => $this->starts_at?->toISOString(),
            'expires_at' => $this->expires_at?->toISOString(),
            
            // Conditional relationships
            'user' => new UserResource($this->whenLoaded('user')),
            'beneficiaries' => BeneficiaryResource::collection($this->whenLoaded('beneficiaries')),
        ];
    }
}
```

### 2.11 Notifications
Use for **multi-channel notifications** (email, SMS, database).

```php
namespace App\Notifications;

class PolicyExpiringNotification extends Notification
{
    public function __construct(
        private Policy $policy
    ) {}
    
    public function via($notifiable): array
    {
        // Send via multiple channels
        return ['mail', 'database', 'sms'];
    }
    
    public function toMail($notifiable): MailMessage
    {
        return (new MailMessage)
            ->subject('Policy Expiring Soon')
            ->line("Your policy {$this->policy->policy_number} expires in 7 days.")
            ->action('Renew Policy', url("/policies/{$this->policy->id}/renew"));

    public function toDatabase($notifiable): array
    {
        return [
            'policy_id' => $this->policy->id,
            'policy_number' => $this->policy->policy_number,
            'expires_at' => $this->policy->expires_at,
        ];
    }
}
```

## 3. Avoiding N+1 Queries

### 3.1 Always Eager Load Relationships

```php
// ❌ Bad - N+1 problem
$policies = Policy::all();
foreach ($policies as $policy) {
    echo $policy->user->name; // Query for each policy
}

// ✅ Good - eager loading
$policies = Policy::with('user')->get();
foreach ($policies as $policy) {
    echo $policy->user->name; // No additional queries
}
```

### 3.2 Nested Relationships

```php
// ❌ Bad
$policies = Policy::with('beneficiaries')->get();
foreach ($policies as $policy) {
    foreach ($policy->beneficiaries as $beneficiary) {
        echo $beneficiary->user->name; // N+1
    }
}

// ✅ Good - nested eager loading
$policies = Policy::with('beneficiaries.user')->get();
```

### 3.3 Conditional Eager Loading

```php
// Load relationships only when needed
$policies = Policy::query()
    ->when($request->include_user, fn($q) => $q->with('user'))
    ->when($request->include_claims, fn($q) => $q->with('claims'))
    ->get();
```

### 3.4 Lazy Eager Loading

```php
$policies = Policy::all();

// Later in code, you realize you need users
if ($needUserData) {
    $policies->load('user'); // Lazy eager load
}
```

### 3.5 Counting Relationships

```php
// ❌ Bad - loads all claims
$policies = Policy::with('claims')->get();
foreach ($policies as $policy) {
    echo $policy->claims->count(); // Already loaded but wasteful
}

// ✅ Good - only count without loading
$policies = Policy::withCount('claims')->get();
foreach ($policies as $policy) {
    echo $policy->claims_count; // No loading, just count
}
```

### 3.6 Existence Checks

```php
// ❌ Bad - loads relationships just to check existence
$policies = Policy::with('payments')->get();
foreach ($policies as $policy) {
    if ($policy->payments->isNotEmpty()) {
        // ...
    }
}

// ✅ Good - use exists
$policies = Policy::withExists('payments')->get();
foreach ($policies as $policy) {
    if ($policy->payments_exists) {
        // ...
    }
}
```

### 3.7 Aggregates on Relationships

```php
// ✅ Good - sum, avg, min, max without loading
$policies = Policy::query()
    ->withSum('payments', 'amount')
    ->withAvg('claims', 'amount')
    ->get();

foreach ($policies as $policy) {
    echo $policy->payments_sum_amount;
    echo $policy->claims_avg_amount;
}
```

### 3.8 Batch Operations

```php
// ❌ Bad - individual queries in loop
foreach ($userIds as $userId) {
    $user = User::find($userId);
    // Process user
}

// ✅ Good - single batch query
$users = User::whereIn('id', $userIds)->get();
foreach ($users as $user) {
    // Process user
}
```

### 3.9 Select Only Needed Columns

```php
// ✅ Good - reduce memory and transfer overhead
$policies = Policy::select(['id', 'policy_number', 'user_id', 'status'])
    ->with('user:id,name,email')
    ->get();
```

### 3.10 Use Chunking for Large Datasets

```php
// ✅ Good - process large datasets without memory issues
Policy::with('user')
    ->chunk(100, function ($policies) {
        foreach ($policies as $policy) {
            // Process policy
        }
    });

// Or use lazy collections
Policy::with('user')
    ->lazy()
    ->each(function ($policy) {
        // Process one by one without loading all
    });
```

## 4. Controllers

### 4.1 Keep Controllers Thin
Controllers should only handle HTTP concerns (request/response).

```php
// ✅ Good - thin controller
class PolicyController extends Controller
{
    public function __construct(
        private PolicyService $policyService
    ) {}
    
    public function store(StorePolicyRequest $request)
    {
        $policy = $this->policyService->create($request->validated());
        
        return PolicyResource::make($policy)
            ->response()
            ->setStatusCode(201);
    }
    
    public function index(Request $request)
    {
        $policies = Policy::query()
            ->with(['user', 'beneficiaries'])
            ->when($request->status, fn($q) => $q->where('status', $request->status))
            ->paginate();
        
        return PolicyResource::collection($policies);
    }
}
```

## 5. Testing

### 5.1 Test Structure
```php
class PolicyServiceTest extends TestCase
{
    use RefreshDatabase;
    
    /** @test */
    public function it_creates_policy_with_beneficiaries()
    {
        // Arrange
        $user = User::factory()->create();
        $data = [
            'user_id' => $user->id,
            'type' => 'health',
            'beneficiaries' => [
                ['name' => 'John Doe', 'relationship' => 'spouse'],

        // Assert
        $this->assertDatabaseHas('policies', ['user_id' => $user->id]);
        $this->assertCount(1, $policy->beneficiaries);
    }
}
```

## 6. Summary Checklist

✅ **Clean Code**
- Short, meaningful comments explaining WHY
- Methods under 20 lines
- Descriptive variable/method names
- One method = one responsibility

✅ **Architecture**
- Actions for single-purpose operations
- Services for complex business logic
- Jobs for queued/async operations
- Events/Listeners for decoupled side effects
- Observers for model lifecycle
- Form Requests for validation
- Policies for authorization
- Resources for API responses

✅ **Performance**
- Always eager load with `with()`
- Use `withCount()`, `withExists()`, `withSum()` for aggregates
- Chunk or lazy load large datasets
- Select only needed columns
- Batch queries instead of loops

✅ **Testing**
- Test business logic in services
- Test validation in form requests
- Test authorization in policies
- Use factories for test data
