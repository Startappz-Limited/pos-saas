# Roles and Permissions Guide

## Package: Spatie Laravel Permission

This project uses [Spatie Laravel Permission](https://spatie.be/docs/laravel-permission) for role and permission management.

**Installation:**

```bash
composer require spatie/laravel-permission
php artisan vendor:publish --provider="Spatie\Permission\PermissionServiceProvider"
php artisan migrate
```

**Version Compatibility:**
- Laravel 11+: `spatie/laravel-permission ^6.0`

---

## 4.1 Authorization Philosophy

Authorization is based on explicit access control, not assumptions.

**Core principles:**

- Permissions grant access, roles group permissions
- No role-based logic in code
- Policies enforce authorization, not controllers
- Permissions are stable; roles are configurable
- Authorization is auditable

## 4.2 Role vs Permission Definition

### Permission

Represents a single allowed action

**Characteristics:**
- Atomic and reusable
- Never tied to UI or routes directly

**Examples:**
- `user.create`
- `user.view`
- `invoice.approve`
- `audit.read`

### Role

A collection of permissions

**Characteristics:**
- Environment and business dependent
- Can change without code changes

**Examples:**
- Admin
- Finance
- Auditor
- Agent

Add UUID and status columns via migration:


### Permission Naming

**Format:** `{module}.{action}`

**Examples:**
- `users.create`
- `users.update`
- `roles.assign`
- `audit.view`

### Role Naming

- Human readable
- Singular

**Examples:**

## 4.5 Model Configuration (Laravel 11+ with Spatie)

### User Model Setup

```php
use Illuminate\Foundation\Auth\User as Authenticatable;
use Spatie\Permission\Traits\HasRoles;

class User extends Authenticatable
{
    use HasRoles;
    
    // Specify guard if using multiple (default is 'web')
    protected $guard_name = 'web'; // or 'api'
    
    // ... rest of model
}
```

### Usage Examples

```php
// Assign role to user
$user->assignRole('Admin');
$user->assignRole(['Admin', 'Finance Manager']);

// Assign permissions directly
$user->givePermissionTo('users.create');
$user->givePermissionTo(['users.create', 'users.update']);

// Remove roles/permissions
$user->removeRole('Admin');
$user->revokePermissionTo('users.create');

// Sync roles (remove all current and assign new)
$user->syncRoles(['Admin']);

// Sync permissions
$user->syncPermissions(['users.create', 'users.view']);

// Check if user has permission
if ($user->can('users.create')) {
    // User has permission
}

// Check if user has role
if ($user->hasRole('Admin')) {
    // User has role
}

// Check multiple permissions (any)
if ($user->hasAnyPermission(['users.create', 'users.update'])) {
    // User has at least one permission
}

// Check multiple permissions (all)
if ($user->hasAllPermissions(['users.create', 'users.update'])) {
    // User has all permissions
}
```

## 4.6 Seeder-Driven Authorization (Mandatory)

All roles and permissions must be seeded.

### Rules

- No manual DB inserts
- Seeders must be idempotent
- Seeders define the source of truth
- UUID generation for extended columns
- Status column set to active by default

### Permission Seeder Example

```php
use Illuminate\Database\Seeder;
use Illuminate\Support\Str;
use Spatie\Permission\Models\Permission;

class PermissionSeeder extends Seeder
{
    public function run(): void
    {
        // Reset cached roles and permissions
        app()[\Spatie\Permission\PermissionRegistrar::class]->forgetCachedPermissions();

        $permissions = [
            // User Management
            ['name' => 'users.view', 'module' => 'users'],
            ['name' => 'users.create', 'module' => 'users'],
            ['name' => 'users.update', 'module' => 'users'],
            ['name' => 'users.delete', 'module' => 'users'],
            
            // Role Management
            ['name' => 'roles.view', 'module' => 'roles'],
            ['name' => 'roles.create', 'module' => 'roles'],
            ['name' => 'roles.update', 'module' => 'roles'],
            ['name' => 'roles.delete', 'module' => 'roles'],
            ['name' => 'roles.assign', 'module' => 'roles'],
            
            // Payment Management
            ['name' => 'payments.view', 'module' => 'payments'],
            ['name' => 'payments.create', 'module' => 'payments'],
            ['name' => 'payments.approve', 'module' => 'payments'],
            ['name' => 'payments.refund', 'module' => 'payments'],
            
            // Audit Management
            ['name' => 'audit.view', 'module' => 'audit'],
            ['name' => 'audit.export', 'module' => 'audit'],
        ];

        foreach ($permissions as $permission) {
            Permission::firstOrCreate(
                ['name' => $permission['name'], 'guard_name' => 'web'],
                [
                    'uuid' => Str::uuid(),
                    'module' => $permission['module'],
                    'status' => 'active',
                ]
            );
        }
    }
}
```

### Role Seeder Example

```php
use Illuminate\Database\Seeder;
use Illuminate\Support\Str;
use Spatie\Permission\Models\Role;
use Spatie\Permission\Models\Permission;

class RoleSeeder extends Seeder
{
    public function run(): void
    {
        // Reset cached roles and permissions
        app()[\Spatie\Permission\PermissionRegistrar::class]->forgetCachedPermissions();

        // Create Super Admin role
        $superAdmin = Role::firstOrCreate(
            ['name' => 'Super Admin', 'guard_name' => 'web'],
            ['uuid' => Str::uuid(), 'status' => 'active']
        );
        
        // Give all permissions to Super Admin
        $superAdmin->givePermissionTo(Permission::all());

        // Create Finance Manager role
        $financeManager = Role::firstOrCreate(
            ['name' => 'Finance Manager', 'guard_name' => 'web'],
            ['uuid' => Str::uuid(), 'status' => 'active']
        );
        
        $financeManager->givePermissionTo([
            'payments.view',
            'payments.create',
            'payments.approve',
            'payments.refund',
            'users.view',
        ]);

        // Create Auditor role
        $auditor = Role::firstOrCreate(
            ['name' => 'Auditor', 'guard_name' => 'web'],
            ['uuid' => Str::uuid(), 'status' => 'active']
        );
        
        $auditor->givePermissionTo([
            'audit.view',
            'audit.export',
            'users.view',
            'payments.view',
        ]);

        // Create Agent role
        $agent = Role::firstOrCreate(
            ['name' => 'Agent', 'guard_name' => 'web'],
            ['uuid' => Str::uuid(), 'status' => 'active']
        );
        
        $agent->givePermissionTo([
            'users.view',
            'users.create',
            'payments.view',
        ]);
    }
}
```

## 4.7 Enum Usage in Authorization

### Permission & Role Status

```php
enum AccessStatus: string
{
    case ACTIVE = 'active';
    case INACTIVE = 'inactive';
}
```

**Status must be enforced at query level:**

```php
// Query only active permissions
$activePermissions = Permission::where('status', AccessStatus::ACTIVE->value)->get();

// Query only active roles
$activeRoles = Role::where('status', AccessStatus::ACTIVE->value)->get();

// Scope for active status
class Permission extends \Spatie\Permission\Models\Permission
{
    public function scopeActive($query)
    {
        return $query->where('status', AccessStatus::ACTIVE->value);
    }
}
```

**Rule:** Inactive roles or permissions grant no access

## 4.8 Middleware Strategy (Laravel 11+ with Spatie)

### Register Middleware

In `bootstrap/app.php` (Laravel 11+):

```php
use Illuminate\Foundation\Application;
use Illuminate\Foundation\Configuration\Exceptions;
use Illuminate\Foundation\Configuration\Middleware;

return Application::configure(basePath: dirname(__DIR__))
    ->withMiddleware(function (Middleware $middleware) {
        $middleware->alias([
            'role' => \Spatie\Permission\Middleware\RoleMiddleware::class,
            'permission' => \Spatie\Permission\Middleware\PermissionMiddleware::class,
            'role_or_permission' => \Spatie\Permission\Middleware\RoleOrPermissionMiddleware::class,
        ]);
    })
    ->create();
```

### Permission Middleware (Preferred)

**Rule:** Routes must check permissions, not roles

```php
// Single permission
Route::get('/users', [UserController::class, 'index'])
    ->middleware('permission:users.view');

// Multiple permissions (user must have all)
Route::post('/users', [UserController::class, 'store'])
    ->middleware('permission:users.create|users.view');

// Multiple permissions (user must have any)
Route::get('/dashboard', [DashboardController::class, 'index'])
    ->middleware('permission:users.view,payments.view');
```

### Role Middleware

**Allowed only for:**
- Admin-only system areas
- Bootstrap access

```php
// Single role
Route::get('/admin', [AdminController::class, 'index'])
    ->middleware('role:Super Admin');

// Multiple roles (user must have any)
Route::get('/finance', [FinanceController::class, 'index'])
    ->middleware('role:Super Admin|Finance Manager');
```

### Combined Middleware

```php
// User must have role OR permission
Route::get('/reports', [ReportController::class, 'index'])
    ->middleware('role_or_permission:Super Admin|audit.view');
```

### Route Groups

```php
// Group routes by permission
Route::middleware(['auth', 'permission:users.view'])->group(function () {
    Route::get('/users', [UserController::class, 'index']);
    Route::get('/users/{user:uuid}', [UserController::class, 'show']);
});

Route::middleware(['auth', 'permission:users.create'])->group(function () {
    Route::get('/users/create', [UserController::class, 'create']);
    Route::post('/users', [UserController::class, 'store']);
});
```

## 4.9 Policy Enforcement (Mandatory - Laravel 11+)

### Rules

- All model-level authorization must use Policies
- Controllers must never contain authorization logic
- Policies internally check permissions

### Policy Example

```php
namespace App\Policies\User;

use App\Models\User\User;
use Illuminate\Auth\Access\HandlesAuthorization;

class UserPolicy
{
    use HandlesAuthorization;

    /**
     * Determine if the user can view any users.
     */
    public function viewAny(User $user): bool
    {
        return $user->can('users.view');
    }

    /**
     * Determine if the user can view the model.
     */
    public function view(User $user, User $model): bool
    {
        return $user->can('users.view');
    }

    /**
     * Determine if the user can create users.
     */
    public function create(User $user): bool
    {
        return $user->can('users.create');
    }

    /**
     * Determine if the user can update the model.
     */
    public function update(User $user, User $model): bool
    {
        // Check permission and business logic
        return $user->can('users.update') && $model->status !== 'locked';
    }

    /**
     * Determine if the user can delete the model.
     */
    public function delete(User $user, User $model): bool
    {
        return $user->can('users.delete') && $user->id !== $model->id;
    }

    /**
     * Determine if the user can restore the model.
     */
    public function restore(User $user, User $model): bool
    {
        return $user->can('users.delete');
    }
}
```

### Register Policy (Laravel 11+)

In `app/Providers/AppServiceProvider.php`:

```php
use Illuminate\Support\Facades\Gate;

public function boot(): void
{
    Gate::policy(User::class, UserPolicy::class);
    
    // Or use auto-discovery by following convention:
    // App\Models\User -> App\Policies\UserPolicy
}
```

### Using Policies in Controllers

```php
class UserController extends Controller
{
    public function index()
    {
        $this->authorize('viewAny', User::class);
        
        $users = User::all();
        
        return view('users.index', compact('users'));
    }

    public function show(User $user)
    {
        $this->authorize('view', $user);
        
        return view('users.show', compact('user'));
    }

    public function update(Request $request, User $user)
    {
        $this->authorize('update', $user);
        
        // Update logic...
        
        return redirect()->route('users.show', $user->uuid);
    }
    
    public function destroy(User $user)
    {
        $this->authorize('delete', $user);
        
        $user->delete();
        
        return redirect()->route('users.index');
    }
}
```

### Using Policies in Views (Blade)

```blade
@can('create', App\Models\User\User::class)
    <a href="{{ route('users.create') }}">Create User</a>
@endcan

@can('update', $user)
    <a href="{{ route('users.edit', $user->uuid) }}">Edit</a>
@endcan

@can('delete', $user)
    <form action="{{ route('users.destroy', $user->uuid) }}" method="POST">
        @csrf
        @method('DELETE')
        <button type="submit">Delete</button>
    </form>
@endcan
```

## 4.10 API Authorization

### Rules

- APIs must validate permissions per endpoint
- Unauthorized requests return: `403 Forbidden`
- No permission leakage in error messages

### API Routes with Permissions

```php
// In routes/api.php
Route::middleware(['auth:sanctum'])->group(function () {
    
    Route::middleware('permission:users.view')->group(function () {
        Route::get('/users', [Api\UserController::class, 'index']);
        Route::get('/users/{user:uuid}', [Api\UserController::class, 'show']);
    });
    
    Route::middleware('permission:users.create')->group(function () {
        Route::post('/users', [Api\UserController::class, 'store']);
    });
    
    Route::middleware('permission:users.update')->group(function () {
        Route::put('/users/{user:uuid}', [Api\UserController::class, 'update']);
    });
    
    Route::middleware('permission:users.delete')->group(function () {
        Route::delete('/users/{user:uuid}', [Api\UserController::class, 'destroy']);
    });
});
```

### API Error Handling

```php
// In app/Exceptions/Handler.php
use Symfony\Component\HttpKernel\Exception\AccessDeniedHttpException;

public function render($request, Throwable $exception)
{
    if ($exception instanceof AccessDeniedHttpException) {
        if ($request->expectsJson()) {
            return response()->json([
                'message' => 'Forbidden',
                'error' => 'You do not have permission to perform this action'
            ], 403);
        }
    }

    return parent::render($request, $exception);
}
```

## 4.11 UI Authorization Rules

- UI must reflect permissions but not enforce them
- Backend remains authoritative
- Disabled actions must explain missing permission

### Blade Directives

```blade
{{-- Check permission --}}
@can('users.create')
    <button>Create User</button>
@else
    <button disabled title="You don't have permission to create users">
        Create User
    </button>
@endcan

{{-- Check role --}}
@role('Super Admin')
    <a href="/admin">Admin Panel</a>
@endrole

{{-- Check any role --}}
@hasanyrole('Super Admin|Finance Manager')
    <a href="/finance">Finance Dashboard</a>
@endhasanyrole

{{-- Check all roles --}}
@hasallroles('Super Admin|Auditor')
    <a href="/audit">Audit Trail</a>
@endhasallroles

{{-- Check permission (Spatie directive) --}}
@permission('users.create')
    <a href="/users/create">New User</a>
@endpermission
```

## 4.12 Cache Management

Spatie package caches permissions for performance. Clear cache when needed:

```php
// Clear permission cache
app()[\Spatie\Permission\PermissionRegistrar::class]->forgetCachedPermissions();

// Or via artisan command
php artisan permission:cache-reset
```

**Clear cache when:**
- After seeding permissions/roles
- After assigning/revoking permissions
- After deployment

## 4.13 Audit Requirements

Authorization changes must be audited:

**Events to Audit:**
- Role creation
- Permission changes
- Role assignments
- Permission revocations

**Audit Details:**
- Actor UUID
- Target UUID
- Action
- Timestamp

### Example Audit Implementation

```php
// Create observer for Role model
namespace App\Observers;

use Spatie\Permission\Models\Role;
use App\Models\AuditLog;

class RoleObserver
{
    public function created(Role $role): void
    {
        AuditLog::create([
            'uuid' => Str::uuid(),
            'actor_id' => auth()->id(),
            'actor_uuid' => auth()->user()?->uuid,
            'action' => 'role.created',
            'target_type' => Role::class,
            'target_id' => $role->id,
            'target_uuid' => $role->uuid,
            'changes' => json_encode($role->toArray()),
        ]);
    }
    
    // Similar methods for updated, deleted, etc.
}

// Register in AppServiceProvider
public function boot(): void
{
    Role::observe(RoleObserver::class);
    Permission::observe(PermissionObserver::class);
}
```

## 4.14 Forbidden Authorization Anti-Patterns

- ❌ Role checks in controllers (use policies and permissions)
- ❌ Hard-coded role names (use constants or enums)
- ❌ Permission logic in views (use Blade directives)
- ❌ Skipping policies (always use policies for model authorization)
- ❌ UI-only authorization (backend must always validate)
- ❌ Exposing internal IDs (use UUIDs for all external references)
- ❌ Not clearing permission cache after changes
